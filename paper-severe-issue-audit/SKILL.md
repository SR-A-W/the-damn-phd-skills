# Paper Severe-Issue Audit — 论文严重问题终审

对一篇即将(或刚刚)提交的论文做最后一道内容安全关。目标不是挑文笔,而是抓**八类一票致命的问题**。方法:PDF 全文 + LaTeX live 源码双面扫描,先宽 regex 撒网、再逐条人工分诊(benign 命中要能说出为什么 benign)。

## 前置

1. 确认审的是**提交版**(拉最新、记下 HEAD hash,全程别动文件)。
2. 重新编译一次,`pdftotext` 出全文文本(下称 `$T`);源码扫描一律**过滤注释行**(注释里的残稿不进 PDF,不算问题,但会污染 grep 结果)。

## 八类扫描(regex 是起点,不是终点)

### 1. AI 生成声明(最低级也最致命)
```
grep -niE "generated by|chatgpt|claude|copilot|written by an? (ai|llm|assistant)|as an ai" $T
```
**Benign 分诊**:引用条目标题里含 AI 产品名(如某论文标题带 "Claude")是合法引用,不是声明。看命中行是正文还是书目。

### 2. Agent/协作工作流泄漏(内部产出贴进了论文)
```
grep -niE "<真实人名> (decided|said)|discussion with|team lead|teammate|working[- ]context|TODO|FIXME|placeholder|NOTE:|APPROVED" $T
```
人名列表用作者名单 + 已知协作者名。同时扫源码里 live 的 `\textcolor{purple/yellow/orange}` 类审阅标记残留。

### 3. 未完实验表述
```
grep -niE "not (yet )?(finished|completed|run)|still running|in progress|pending|to be (added|filled|determined)|TBD|coming soon|did not have time" $T
```
**Benign 分诊**:"we did not run X as baselines(+理由)"是合法的 scope 声明(方法论选择),与"实验没跑完"不同——判据:有没有给出**主动的、站得住的理由**,还是暴露了流程未完成。

### 4. 缺陷自认(≠局限性)
```
grep -niE "flaw|defect|broken|we acknowledge that our .* (fails|is wrong)|serious limitation|weakness of our|unfortunately" $T
```
Limitations 章节里克制的边界讨论是应该的;**"我们的方法有缺陷/做错了"级别的自认**才是错误。逐条读上下文定性。

### 5. 改名/换口径后的旧称残留
项目中途改过的一切名字都要建清单逐一清零:方法旧名、模型旧名、旧基座、旧数据集规模口径、旧指标口径。
```
grep -n "<旧名1>\|<旧名2>\|..." $T    # 以及 live 源码
```
本类没有通用 regex——**执行时先向用户/项目文档要"改名清单"**,再逐项扫。

### 6. 修订过程叙事(读者不知道有 rebuttal)
```
grep -niE "newly added|rebuttal|reviewer|revised version|camera.ready|in this (revision|version)|as requested|per the (review|meta)" $T
```
论文必须以**永恒读者视角**成立:读者看到的是"一篇论文",不是"一次修订"。任何 "newly added / 应审稿人要求" 都是不知所云的叙事泄漏。

### 7. Desk-reject 项(格式红线)
- **模板完整性**:从官方仓库拉正式模板,对 `.sty/.bst` 逐字节 `diff`(必须 IDENTICAL);
- **禁包扫描**(live 行):`savetrees|geometry|setspace|titlespacing|linespread|baselinestretch|addtolength`(注释掉的不算);
- 类选项:camera-ready 用 `[final]`(或该会议规定项);PDF 无行号;
- 页限:按会议规则数正文页(References/Acknowledgments 通常不计——**查该会议官方模板注释确认**);
- `pdffonts` 全部字体嵌入;
- 占位符扫描:`TBD|XXX|\[X\.X\]|BASE_MODEL_NAME|lorem` (注意:占位符可能活在**未 \input 的死文件**里——先从主 tex 的 `\input` 清单确定哪些文件是 live 的);
- 编译 error 计数 = 已知基线(理想为 0)。

### 8. 相关工作人称错位(作者有重叠时最易犯)
本文作者可用 "we";**引用他人论文(哪怕作者与本文部分重叠)一律第三人称**。
```
grep -niE "our (previous|prior|earlier) work|we (showed|demonstrated|found) in \[|building on our" $T
```
再对**已知的强相关前作**(往往是同组的)逐处抽查引用上下文,确认全部是 "X et al. (year) showed/explored..." 句式。

## 输出格式

一张八行裁决表(✅/🔴 + 一句话依据),之后:
- **真问题清单**:file:line、原文、为什么严重、最小修复建议;
- **Benign 命中说明**:命中了但不算问题的,逐条给出理由(这是审计可信度的来源——"零命中"和"命中但经分诊为良性"要区分开);
- 顺手抓到的**非严重但真实的 typo/小错**单独列出,修不修由用户定(提交后若窗口未关,单点修复+回冻)。

## 纪律

- **只读**。审计过程绝不改文件;修复必须拿到用户明确指令后单点执行,改完立即回到冻结状态。
- 每个 🔴 都要给 file:line 级证据;每个 ✅ 都要真的跑过对应扫描,**不写没执行过的验证声明**。
- 扫描命令与命中数记入报告,便于复核。
