# Preprint Release — 整理成预印版(arXiv 等)工作流

把一个 LaTeX 项目(通常是 Overleaf 仓)整理成 arXiv 上传 zip。核心事实:**arXiv 公开完整源码**——读者能看到每一行注释、每个文件名、每条 bib。所以这不是打包,是一次"源码即将公开"的安全清理。

> **总纲——作用域纪律**:一个「通过」所提供的保证,上限是它的作用域;每报告一项验收通过,同时说明这项检查看不见什么。执行每一步时固定自问:**这一步失败时,我能在当场拿到什么信号?** 答案是"没有"的地方(信号延迟到别的环境/平台侧、或被噪音淹没),要主动构造一个能证伪的信号,而不是把"没报错"当"通过"。

## 调用形态

```
/preprint-release <论文仓路径> [可选:输出名/备注]
```

## 总流程(8 步,顺序执行,每步有验收)

### 1. 副本隔离(不可协商)
- `git pull` 拿最新 → 复制整个项目到独立工作目录(scratchpad),**正式仓一个字节不动**。
- 记下源 HEAD hash。
- **环境依赖预检(在首次编译之前做)**:精简 TeX 发行版只装最小宏包集,首次编译可能直接以 `File 'xxx.sty' not found` fatal 终止、不产出 PDF——这与清理无关,却会把执行者挡在第一步。迭代「编译 → 抓缺失宏包 → 用发行版包管理器安装 → 重编」直到干净,再开始正式流程。两个易踩的点:包管理器**自身可能需要先自更新**才装得动(否则报错退出,容易被误判为装不了);并确认缺失是**环境本来就缺**(未做任何改动的原状态同样编不过),而不是本流程引入的——这个对照能把"环境不全"和"你改坏了"区分开。
- **建立 diff 基线**:最终验收之一 = 清理后副本渲染与基线渲染 `pdftotext` 逐字 diff = 0(内容零漂移的硬证据)。基线必须是**未做任何清理的原始源码、以与最终产物相同的排版模式/文档类选项编译出的 PDF**,存为 `baseline.pdf` 与 `baseline.txt`。
  - 会议模板普遍带模式开关(匿名投稿版 / 预印版 / 正式版之类,如 ACL 的 `review`/`preprint`/`final`,其他模板同理)。**若发布版要切换模式,先切模式编出基线,再做清理**:模式切换本身就会改变作者块、行号、页码,直接拿清理后副本与原始正式版渲染 diff,基线不可比、恒不为 0——验收要么被误判为失败,要么被随手放行,两种都等于验收失效。
  - 原则:基线与被测产物之间的**唯一变量必须是清理动作**;模式差异必须事先烘焙进基线。
  - 若发布版与正式版模式完全相同(不切模式),基线就是正式版渲染。
  - **发布版若有故意的内容变更**(去匿名化后换真实代码/数据仓链接、补回匿名期删掉的致谢与资助编号、加"已被某会议接收"之类的版本说明、更新联系方式……),**同样要事先烘焙进基线**,做法与模式切换对称:先把这些变更施加到基线上得到 `baseline_v2`,**并单独验证这一步**——`baseline` → `baseline_v2` 的差异**恰好等于意图、不多不少**(比较方法见步骤 7);此后步骤 7 的 diff=0 一律改对 `baseline_v2`。
  - 不这么拆,故意的改动与意外的内容漂移在同一个 diff 里**无法区分**,执行者只剩两个都错的选择:放弃 diff=0 改人工判读(等于把两者一起放行),或硬守 diff=0(流程无法完成)。**清理动作的验收与内容变更的验收,各自成立、互不污染。**
  - 一并记录基线的 **error 数、页数、`[?]` 数**,作为步骤 7「0 新增 error」的对照组——没有这个锚点,"新增"就没有可执行的定义。
- 先删:`.git`、`*.aux/log/out/blg/pdf`、README(仓库自述,非论文内容)、`__pycache__` 等。

### 2. 死文件与敏感文件名(在剥注释**之前**做,因为要看注释判断)
- 从主 tex 的 `\input`/`\include` 清单确定 **live 文件集**;未被引入的死章节文件(常含占位符、TBD、废稿)**整个删除**。
- **文件名审查(两个独立维度:信息泄漏 + 目标平台兼容性)**——文件名既会被公开,也要能被目标平台的构建系统正确处理:
  - 暴露 AI 参与的名字(如 `gpt_formalization_problem.tex`)→ 改中性名(`formal_specification.tex`),同步改主 tex 的 `\input`;
  - 含个人名字的文件(`method_<somename>.tex`)→ 改中性名;
  - **含空格或非 ASCII 字符的文件名**(各种破折号、带重音字母、全角标点)→ 改为纯 ASCII 无空格名。本地 TeX 发行版通常宽容,远端自动构建系统未必;这类风险**在本地不产生任何信号、无法在本地证伪**,但本地改名成本极低且可逆,发布后才发现则要重新提交一版。图文件名直接取自绘图工具导出标题时最常见(天然带空格,连接符常是排版长破折号而非 ASCII 连字符)。
  - 改名后重编译确认无 missing file。
- **内部开发史注释/字符串**:代码级正文里若有 "V2 broken / 失效版 / fed to GPT-x" 类叙述(哪怕在将被保留的 live 文件里),改写为中性技术表述。

### 3. 注释全剥
- 用 **`arxiv-latex-cleaner`**(`pip install arxiv-latex-cleaner; python -m arxiv_latex_cleaner --keep_bib <dir>`)——它正确处理 `\%` 转义、verbatim 环境;**不要手写 regex 剥注释**(跨行色组、行尾 % 都是坑)。
- **`--keep_bib` 不是可选项**:该工具默认**删除 `.bib`**,而这正是事故档案 #1 描述的翻车原因。漏掉这个 flag,本地因为有 `.bbl` 照样编译通过、全程零报错,**信号要等到换一个强制跑 BibTeX 的环境才出现**。(此处与事故档案 #1 互相指认,避免日后被改回去。)
- 注意它**默认输出到新目录**(`<dir>_arXiv`)而非原地修改,跑完同时存在两个副本。约定:**以输出目录为后续步骤的权威副本**,步骤 4~7 一律在它上面做;原副本只留作对照,不再改动。
- 验收:`grep -rn "^%"` 与行内注释抽查 = 0;审阅色标记、归档原文、蓝色旧稿等全部随注释消失。

### 4. bib 净化
- 从**步骤 1 基线编译产生的** `.bbl` 反查全部被引 key(`\bibitem[...]{key}`),用 brace-aware 解析从原 bib 抽出**仅被引条目**,重写 bib。草稿期未引条目(可能暴露放弃的方向)不外泄。
- 本步依赖一份**已经存在的** `.bbl`,而全流程第一次编译发生在步骤 1(建基线)——跳过基线直接跑到这里,手上不会有 `.bbl`,流程会卡死。基线编译是本步的前置,不可省。
- **`.bbl` 和净化版 `.bib` 都要打包**:arXiv 编译认 `.bbl`(无需跑 bibtex),但作者常会把包丢回 Overleaf 验证——Overleaf 强制跑 BibTeX,没有 `.bib` 就全文引用爆炸(实战翻过车)。
- 断言:被引 key 在净化 bib 中 100% 命中,一条不缺。

### 5. 图与资源瘦身
- 重新扫描剥注释后的 live `\includegraphics`,只保留被引用的图文件(注释里引用的图已随注释死亡,常能砍掉 3/4)。
- 留意同名不同扩展名(`.png` vs `.pdf`)只保留被用的那个;检查非 figures 目录下的散图。
- **删图后立即重编译,确认 0 missing figure**——与步骤 2 改名后的重编译验收对称。误删一个实际被引用的图,若拖到步骤 7 才暴露,返工代价高。

### 6. AI 痕迹与遗留占位终扫
- 清理后源码 + 渲染 PDF 双面扫:`chatgpt|claude|copilot|generated by|GPT-[0-9]|as an ai`(**合法引用条目/论文标题除外**,逐条分诊);
- 占位符扫:`TBD|XXX|\[X\.X\]|placeholder|lorem`;
- 若项目做过改名/换口径,旧名清单也扫一遍。
- (若装有 `paper-severe-issue-audit` skill,可直接对副本跑其八类扫描替代本步。)

### 7. 独立编译验证 → 打包
- 副本内完整循环:`pdflatex → bibtex → pdflatex ×2`;验收:**0 新增 error、`[?]`=0、页数与步骤 1 的基线一致、pdftotext 与 `baseline.txt` 逐字 diff=0**。
  - **页数与 diff 的比较对象都是步骤 1 的基线,不是正式版渲染**——两者模式不同时跨模式比较恒不相等,等于没验收。
  - **逐行 diff 不足以判读,要提升到规范化后的词级比较**:`pdftotext` 保留 PDF 的换行位置,而 LaTeX 按行宽重新断行——**一处极小的文字长度变化会让该段之后整段重新折行**,逐行 diff 因此输出成十上百行,真假差异混在一起,肉眼无法分辨(长 URL 还会在 `/` 处被折成两行,进一步干扰)。做法:①规范化(去换行、重新拼接被折断的长串、压缩连续空白);②做词序列比较;③验收标准改为**差异块数量 = 预期改动处数,且每块内容与意图逐字相符**。这样得到的是可证伪的判据("全文仅 N 处差异,分别是 X、Y、Z"),而不是"看起来只有那处改动"。
  - diff 非 0 时逐条归因到具体清理动作(删了哪个文件 / 剥了哪段注释 / 净化 bib 掉了哪个 key);只有确认无内容影响的差异才可放行,且在报告里逐条写明理由。
- **(可选,但能直接证伪事故档案 #1)** 在最终包的副本上**删掉 `.bbl` 强制跑 BibTeX** 编译一次,确认 `couldn't open database` 出现 0 次、引用全部解析、渲染与基线 diff 仍为 0——这模拟的正是作者把包丢回强制跑 BibTeX 的环境验证时的场景。
- 删除编译产物(pdf/aux/log/blg),`zip -rq` 打包。**渲染出的页要真的读几页**,不能只看退出码。

### 8. 提交页元数据把关(用户在 arXiv 网页操作,agent 出核对清单)
- **摘要纯文本化**:LaTeX 宏展开(自定义命令如 \think{} → 实际字符)、`---` 在 arXiv 摘要不渲染成破折号(手改为 " — " 或标点)、`\times`/× 写 x、`$...$` 数学 MathJax 可留但需预览确认;
- **分类字段**:MSC-class 是数学分类(68Txx 形态),`I.2.7` 这类是 **ACM-class**——别填错字段;CS 论文 MSC 通常留空;
- 作者列表与论文作者块逐一核对(人数、顺序、拼写);
- Comments 的页数/图数/表数与实际一致;
- **License 提醒**:CC BY 系不可撤销的宽松授权,arXiv 默认非独占 license 更保守——确认用户是知情选择;
- 预览页 PDF + HTML 双转换 Success 后再 Submit。

## 增量 re-pack(正式版又改了)
重新从最新 HEAD 走完整 8 步(脚本化后约 2 分钟)——**不要**在旧包上手工打补丁;每版 zip 带版本号(v1/v2/v3...),报告里写明基于哪个 HEAD。

## 事故档案(实战翻过的车,执行时自查)
1. **只打包 .bbl 不打包 .bib** → 用户丢回 Overleaf 验证时 BibTeX 报 "couldn't open database",全文引用变 undefined。两个都带。
2. **敏感信息在文件名而非文件内容里**(gpt_*.tex)——grep 内容扫不到,必须单独过一遍文件名清单。
3. **元数据字段错位**(ACM 分类填进 MSC-class)——提交预览页要整页截图级逐字段核对。
4. **摘要三连字符 `---` 原样显示**——arXiv 摘要是纯文本不是 LaTeX。
5. 匿名期遗留("anonymous snapshot"、"Notes for Reviewers"、Anonymous Authors 版权头)在 de-anonymize 后仍残留——公开前全仓扫 `anonym|reviewer`。
